% 2. INTRODUCTION TO THE PROBLEM DOMAIN
% ============================================================
\begin{frame}{Introduction to the Problem Domain}
  \begin{itemize}
    \item Our project is in the area of Big Data Analytics applied to Smart Transportation --- specifically taxi demand forecasting, fare estimation, and trip duration (ETA) prediction.
    \item Modern cities and ride-hailing platforms create massive data every second: pickup points, dropoff points, timestamps, trip distances, and fares.
    \item \textbf{Why this matters:}
      \begin{itemize}
        \item Mismatch between taxi supply and passenger demand causes long passenger wait times and wasted fuel for idle drivers.
        \item Unexpected weather changes and traffic spikes create price confusion and delays.
      \end{itemize}
    \item Older, single-machine tools (Excel, Pandas, standard SQL) crash when handling 100+ million trip records or streaming live data.
    \item Big Data tools like Hadoop HDFS and Apache Spark are built to process this volume of data quickly and support real-time mobility decisions.
  \end{itemize}
\end{frame}

% ============================================================
% 3. PROBLEM STATEMENT
% ============================================================
\begin{frame}{Problem Statement}
  \begin{block}{Problem Statement}
    Current taxi demand forecasting, fare prediction, and ETA estimation tools are usually built as separate small-scale projects using static datasets. Most do not combine historical trip patterns with weather conditions, and cannot process live streaming data efficiently. Our project builds one unified Big Data framework using Hadoop HDFS and Apache Spark that cleans 12+ million records, handles schema drift, forecasts zone-wise taxi demand for the next hour, and predicts trip fare and ETA in real time.
  \end{block}
\end{frame}

% ============================================================
% 4. OBJECTIVES
% ============================================================
\begin{frame}{Objectives}
  \begin{itemize}
    \item Develop a scalable Hadoop--Spark framework for real-time urban transportation analytics using NYC TLC taxi and Open-Meteo weather datasets.
    \item Implement automated data cleaning at scale using Scala Spark to filter noisy records (negative fares, zero distance, GPS glitches) across 13 veracity rules.
    \item Enrich datasets with spatial and weather features using broadcast joins with 265 NYC Taxi Zones and hourly temperature/rain data.
    \item Train Spark MLlib machine learning models to predict hourly zone demand, trip fare, and trip duration (ETA).
    \item Build a real-time streaming pipeline using Apache Kafka and Spark Structured Streaming for live trip processing.
    \item Create an interactive decision dashboard with live demand heatmaps and fare/ETA prediction widgets.
  \end{itemize}
\end{frame}

% 6. 5VS OF BIG DATA
% ============================================================
\begin{frame}{5Vs of Big Data}
  \begin{itemize}
    \item \textbf{Volume:} Processes large-scale NYC Taxi datasets (17.25 GB raw, 12.1+ million trip records across 2022--2024) using Hadoop HDFS.
    \item \textbf{Velocity:} Spark Structured Streaming and Kafka enable near real-time processing of continuous trip streams.
    \item \textbf{Variety:} Integrates structured taxi trip Parquet files, spatial 265 Taxi Zone CSVs, and semi-structured Open-Meteo weather JSON.
    \item \textbf{Veracity:} Improves data reliability through 13 Scala Spark veracity cleaning rules, filtering 737,000+ noisy records.
    \item \textbf{Value:} Generates actionable mobility insights (Demand Heatmaps, Fare Quotes, ETA Alerts), enabling faster driver allocation and passenger planning.
  \end{itemize}
\end{frame}

\begin{frame}{Proposed System (1/3)}
  \textbf{Overview}
  \begin{itemize}
    \item The proposed framework integrates Taxi Demand Forecasting, Fare Prediction, and ETA Estimation into a single unified Hadoop--Spark architecture.
    \item Store multi-year NYC Taxi trip datasets and weather records in Hadoop HDFS.
    \item Perform data preprocessing including schema unification, cleaning, and feature extraction using Scala Spark.
    \item Enrich trip records with 265 Taxi Zones using broadcast joins to avoid network shuffle.

% 12. CHALLENGES / LIMITATIONS
% ============================================================
\begin{frame}{Challenges / Limitations}
  \begin{itemize}
    \item \textbf{Schema Desync Across Years:} TLC changed physical column types in 2023 Parquet files (\texttt{INT64} to \texttt{INT32}), requiring explicit casting in \texttt{SchemaUnifier.scala}.
    \addlinespace
    \item \textbf{Month-by-Month Ingestion:} Wildcard scans across multi-year folders caused RDD inference errors; solved by month-by-month Spark reader loop.
    \addlinespace
    \item \textbf{Driver Memory Management:} Processing 12M+ records required driver memory tuning (\texttt{--driver-memory 4g}) to prevent OutOfMemory errors.
    \addlinespace
    \item \textbf{Data Veracity Noise:} 737,003 records contained negative fares, zero distances, or taximeter glitches requiring 13 explicit cleaning rules.
    \addlinespace
    \item \textbf{Container Networking:} YARN containers required explicit RPC hostname resolution in Docker.
  \end{itemize}
\end{frame}
